# 전체 본문 수집과 읽기

2026-09-13부터 피드의 앞부분만 분석하던 제한을 제거했다. 수집 가능한 텍스트를 보존하고, 긴 글은 모든 구간을 읽어 종합 분석에 사용할 요약을 저장한다.

## 사용자 동작

- 새 글은 수집·자동 분석 때 적용된다. 기존 피드 글도 다음 다이제스트 입력으로 사용될 때 준비한다.
- Feed/보관함 카드에서 **원문 내용 보기**를 펼치면 저장 본문과 수집 상태를 확인할 수 있다. 이 조회 자체는 LLM을 호출하지 않는다.
- **원문·전체 요약 갱신**은 원문을 재수집하고 종합 입력을 준비한다. 본문·설정이 같으면 저장된 요약을 재사용한다. 별점·분류·기존 분석 시각은 바꾸지 않는다.
- 이미 저장된 보고서는 자동으로 다시 생성하지 않는다. 새 내용을 반영하려면 해당 기간의 새 다이제스트를 생성한다.

## 수집 범위

RSS 및 일반 글은 원문 URL의 HTML에서 본문을 추출한다. 네이버 블로그의 본문 iframe과 소스별 본문 선택자를 지원하며 나머지는 Readability를 사용한다. 제공 본문과 원문 추출 결과가 서로 다른 경우 제공 본문을 함께 보존한다.

X·텔레그램은 게시글을 보존한 뒤 직접 연결된 페이지의 텍스트를 별도 구분해 추가한다. 링크 안의 또 다른 참고 문헌까지 재귀 수집하지 않는다. 원문 자체가 2차 전언이면 전체 텍스트 수집 후에도 2차 전언일 수 있다.

`원문 페이지 본문 추출`은 HTML 본문 추출에 성공했다는 뜻이다. 이미지/차트 OCR, PDF 읽기, 모든 동적 페이지 지원이나 유료 본문 전체 확보를 뜻하지 않는다. 접근 실패·인식 가능한 유료 미리보기·연결 원문 실패는 `일부 수집`으로 표시한다. 해당 소스에 이미 저장된 로그인 세션이 있을 때만 인증 본문 추출을 시도한다.

공개 HTTP 수집은 외부 주소를 검증하고 DNS 결과를 고정하며 이동 URL마다 다시 검사한다. 일반 페이지 제한은 요청당 15초, 이동 5회, 압축 해제 후 2MiB다. 제한에 걸리면 일부 수집으로 남기며 실패를 본문 절단 성공으로 취급하지 않는다.

## 전체 읽기와 비용

`analysis/fullReading.ts`는 수집 텍스트를 12,000자 단위로 손실 없이 나눈다. 짧은 본문은 추가 요약 호출 없이 그대로 사용한다. 긴 글은 자료 정리 모델로 모든 구간을 읽고, 요약 합계가 길면 다시 모든 요약을 압축한다. 출력 요약 자체는 원문과 동일한 전문이 아니며 압축 과정에서 세부 정보가 줄어들 수 있다. 원래 수집 텍스트는 별도로 보존한다.

자료 정리 모델·Thinking 선택은 기존 Settings를 따른다(기본 OFF). 장문 첫 읽기에는 호출 비용이 추가되지만 이후 선별·다이제스트는 저장 결과를 재사용한다. 본문·수집 범위·모델·Thinking·요약 지침·읽기 프롬프트가 달라지면 캐시를 다시 만든다. 모델 ID가 같은 별칭의 서버 측 버전 변경은 자동으로 감지하지 않는다.

구간마다 체크포인트를 저장한다. 실패한 글은 완성으로 표시하지 않으며 다음 시도에서 완료 구간을 재사용한다. 피드 기반 다이제스트는 전체 읽기 실패를 숨기고 해당 글만 누락한 보고서를 저장하지 않는다. 기존 다이제스트들을 재종합하는 별도 경로도 모든 저장 텍스트를 읽지만 중간 요약은 영구 저장하지 않는다.

## 데이터와 배포

`0014_full_article_reading.sql`은 `articles`에 nullable 필드 3개를 추가한다.

| 필드 | 내용 |
| --- | --- |
| `source_body` | 어댑터가 제공한 원래 본문. 재수집 시 연결 기사의 중복 추가 방지 |
| `content_meta` | 수집 상태, 직접 연결 URL, 실패 이유, 추출 대기 여부 |
| `reading_cache` | 본문/설정 해시, 완료 구간, 종합용 텍스트, 완료 시각 |

Railway 시작 명령의 `db:migrate`가 적용한다. 기존 글은 필요할 때 준비하며 부팅 때 전체 재분석하지 않는다. 영구삭제는 새 본문/캐시도 지우고 중복 수집 방지용 묘비를 남긴다. 새 환경변수는 필요 없으며 기존 `FILTER_BODY_CHARS`, `DIGEST_ITEM_CHARS`, `MAX_BODY_CHARS`는 사용하지 않는다.

## 검증

`tests/fullArticle.test.ts`에서 전체 텍스트·끝 문단·이모지, HTML 추출, 제공 본문 보존, 연결 기사 분리·부분 실패, 내부 주소 차단, 캐시 재사용·변경 감지·중단 재개, 선별 입력·다이제스트 크기 계산을 확인한다. 전체 테스트 156/156·타입 검사·프로덕션 빌드가 통과했다. 실제 공개 한국경제 기사 2건은 RSS 본문이 비어 있어도 원문 1,891자/3,700자를 추출했다. 로컬 데모에서 본문·수집 상태·저장 요약·갱신 버튼 표시를 확인했다. 운영 계정의 실제 LLM 보고서 생성은 이 검증에 포함하지 않았다.
