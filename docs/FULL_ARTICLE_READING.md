# 전체 본문 수집과 읽기

2026-09-13부터 피드의 앞부분만 분석하던 제한을 제거했다. 수집 가능한 텍스트를 보존하고, 긴 글은 모든 구간을 읽어 종합 분석에 사용할 요약을 저장한다.

## 사용자 동작

- 새 글은 수집·자동 분석 때 적용된다. 기존 피드 글도 다음 다이제스트 입력으로 사용될 때 준비한다.
- Feed/보관함 카드에서 **원문 내용 보기**를 펼치면 저장 본문과 수집 상태를 확인할 수 있다. 이 조회 자체는 LLM을 호출하지 않는다.
- Settings의 **자동 분석 재시도 관리 → 처리 내역**은 보류 글의 저장 본문·완료 요약 표본·분할/복구 상태·학습된 입력 상한·최근 API 호출 최대 30건을 조회한다. 기존 인증이 필요하며 AI 호출, 재수집, 보류 해제를 하지 않는다. 부모·자식 요약을 함께 저장하므로 캐시 개수나 글자 합계는 고유 원문 처리량이 아니다.
- **원문·전체 요약 갱신**은 원문을 재수집하고 종합 입력을 준비한다. 본문·설정이 같으면 저장된 요약을 재사용한다. 별점·분류·기존 분석 시각은 바꾸지 않는다.
- 이미 저장된 보고서는 자동으로 다시 생성하지 않는다. 새 내용을 반영하려면 해당 기간의 새 다이제스트를 생성한다.

## 수집 범위

RSS 및 일반 글은 원문 URL의 HTML에서 본문을 추출한다. 네이버 블로그의 본문 iframe과 소스별 본문 선택자를 지원하며 나머지는 Readability를 사용한다. 제공 본문과 원문 추출 결과가 서로 다른 경우 제공 본문을 함께 보존한다.

X·텔레그램은 게시글을 보존한 뒤 직접 연결된 페이지의 텍스트를 별도 구분해 추가한다. 링크 안의 또 다른 참고 문헌까지 재귀 수집하지 않는다. 원문 자체가 2차 전언이면 전체 텍스트 수집 후에도 2차 전언일 수 있다.

`원문 페이지 본문 추출`은 HTML 본문 추출에 성공했다는 뜻이다. 이미지/차트 OCR, PDF 읽기, 모든 동적 페이지 지원이나 유료 본문 전체 확보를 뜻하지 않는다. 접근 실패·인식 가능한 유료 미리보기·연결 원문 실패는 `일부 수집`으로 표시한다. 해당 소스에 이미 저장된 로그인 세션이 있을 때만 인증 본문 추출을 시도한다.

공개 HTTP 수집은 외부 주소를 검증하고 DNS 결과를 고정하며 이동 URL마다 다시 검사한다. 일반 페이지 제한은 요청당 15초, 이동 5회, 압축 해제 후 2MiB다. 제한에 걸리면 일부 수집으로 남기며 실패를 본문 절단 성공으로 취급하지 않는다.

## 전체 읽기와 비용

`analysis/fullReading.ts`는 12,000자 이하 본문을 추가 요약 호출 없이 그대로 사용한다. 긴 글은 기존 캐시 호환용 12,000자 기본 구간을 유지하되, 미완료 구간은 첫 API 요청 전에 최대 6,000자씩 무손실 이등분한다. 모든 문자·끝 문단·이모지 쌍을 입력에 포함한다. 자료 정리 모델로 모든 구간을 읽고 요약 합계가 길면 다시 모든 요약을 압축한다. 출력 요약 자체는 원문과 동일한 전문이 아니며 압축 과정에서 세부 정보가 줄어들 수 있다. 원래 수집 텍스트는 별도로 보존한다.

2026-09-22부터 내부 전체 읽기 지침과 사용자에게 보여줄 Feed 요약 지침을 분리한다. 내부 읽기는 서로 다른 사건·주체·수치·날짜·가격·제품·조건·반론·결론을 짧은 사실 항목으로 압축한다. 원문에 있는 영향·가설을 보존하되 새로운 투자 해석·연결 가설을 만들어 분량을 늘리지 않는다. 기존 사용자 요약 지침은 후속 선별에 그대로 적용한다. 선별은 늘어난 전체 입력에 맞춰 기본 출력 상한을 1,600토큰(논지 목록이 있으면 2,800)으로 조정하고 DeepSeek JSON 모드를 사용한다. 원문·판단 기준을 줄이지 않고 완성 JSON을 받을 여유를 확보하는 상한이며 고정 소비량은 아니다.

자료 정리 모델·Thinking 선택은 기존 Settings를 따른다(기본 OFF). 구간당 출력 상한은 OFF일 때 3,200토큰이다. 장문 첫 읽기에는 호출 비용이 추가되지만 이후 선별·다이제스트는 저장 결과를 재사용한다. 본문·수집 범위·모델·Thinking·사용자 요약 지침이 달라지면 캐시를 다시 만든다. 이번 내부 지침 수정은 기존 캐시 키 계산을 호환용으로 유지하므로 완료된 전체 읽기·기본 구간·하위 구간을 일괄 무효화하지 않는다. 사용자 요약 지침도 이 호환 키에는 계속 포함되지만 내부 API 프롬프트에는 주입하지 않는다. 모델 ID가 같은 별칭의 서버 측 버전 변경은 자동으로 감지하지 않는다.

구간마다 체크포인트를 저장한다. 출력 제한으로 실패하면 해당 구간을 추가 이등분하고 실패한 상위 구간의 계획을 하위 호출 전에 저장한다. 복구는 최대 3단계·추가 호출 24회이며 정상 사전 분할 호출은 이 보정 횟수에 포함하지 않는다. 해결되지 않으면 보류하고 잘린 응답을 완성 요약으로 저장하지 않는다. 새 복구 정책 v2는 이전 미완료 보류를 한 번 해제하되 완료 구간·기존 분할 계획을 보존한다. 같은 정책에서 재보류된 글은 자동으로 다시 풀지 않는다. 명시적 해제도 성공 구간을 재사용한다. 재시도·사용량 상세는 [LLM 사용량](LLM_USAGE.md)을 참고한다.

9/22 저녁 수정은 **한 글에서 배운 입력 상한을 이후 미완료 구간에 적용**한다. 예를 들어 6,000자 입력이 잘리면 무손실 반분 크기인 약 3,000자를 `recovery.inputCharLimit`에 먼저 저장하고, 같은 글의 뒤 구간도 유료 호출 전에 그 크기로 나눈다. 더 작은 구간이 실패하면 다시 낮추며, 앞 구간의 성공을 근거로 자동 상향하지 않는다. 보관된 실패 분할 계획은 완료 부모 안의 하위 계획까지 읽어 상한을 추론하므로 이미 실패한 큰 구간을 재호출할 필요가 없다. 이 사전 분할은 정상 처리이며 보정 횟수를 소모하지 않는다. 실패 직후 하위 보정에는 기존 최대 3단계·24회가 적용되고, 3,000자 미만 구간이 실패하면 해당 실행을 보류한다.

학습된 상한은 명시적 재시도에서도 완료 구간·분할 계획과 함께 유지한다. 기존 `policy:2`, 분석 설정 지문, 캐시 키는 바꾸지 않으며 이미 보류된 글을 일괄 해제하지 않는다. 같은 글의 여러 구간 실패가 누적될 수 있으므로 사용량 화면의 글별 실패 합계가 동일 구간 반복 요청을 뜻하지는 않는다. 더 작게 나누는 처리는 입력 전체를 보존하지만 실제 모델의 요약 품질이나 모든 글의 성공을 보장하지는 않는다.

피드 기반 다이제스트는 전체 읽기 실패를 숨기고 해당 글만 누락한 보고서를 저장하지 않는다. 기존 다이제스트들을 재종합하는 별도 경로도 모든 저장 텍스트를 읽지만 중간 요약은 영구 저장하지 않는다.

## 데이터와 배포

`0014_full_article_reading.sql`은 `articles`에 nullable 필드 3개를 추가한다.

| 필드 | 내용 |
| --- | --- |
| `source_body` | 어댑터가 제공한 원래 본문. 재수집 시 연결 기사의 중복 추가 방지 |
| `content_meta` | 수집 상태, 직접 연결 URL, 실패 이유, 추출 대기 여부 |
| `reading_cache` | 본문/설정 해시, 완료 구간, 종합용 텍스트, 완료 시각, 복구 정책·사전/실패 분할 계획·학습된 입력 상한·추가 호출 횟수·보류 |

Railway 시작 명령의 `db:migrate`가 적용한다. 기존 글은 필요할 때 준비하며 부팅 때 전체 재분석하지 않는다. 영구삭제는 새 본문/캐시도 지우고 중복 수집 방지용 묘비를 남긴다. 새 환경변수는 필요 없으며 기존 `FILTER_BODY_CHARS`, `DIGEST_ITEM_CHARS`, `MAX_BODY_CHARS`는 사용하지 않는다.

## 검증

9/13 도입 당시 `tests/fullArticle.test.ts`를 포함한 156개 테스트·타입 검사·프로덕션 빌드가 통과했다. 실제 공개 한국경제 기사 2건은 RSS 본문이 비어 있어도 원문 1,891자/3,700자를 추출했다. 로컬 데모에서 본문·수집 상태·저장 요약·갱신 버튼 표시를 확인했다. 운영 계정의 실제 LLM 보고서 생성은 이 검증에 포함하지 않았다.

9/22의 `fullReadingRecovery.test.ts`·`fullArticle.test.ts`·`readingCacheRace.test.ts` 33개 가상 호출 테스트는 내부 프롬프트 분리, 첫 요청 최대 6,000자, 전체 문자/끝 사건 보존, 구 캐시 해시·완료 하위 구간 재사용, 정책 전환 시 한 번만 보류 해제, 보정 호출 상한, 수집 경쟁·삭제 후 쓰기 방어를 검증한다. 추가된 입력 상한 학습은 72,000자 가상 글의 실패를 12회에서 1회로 줄였고, 78,000자 글도 실패 13회 후 보류 대신 실패 1회 후 완성했다. 중단 후 기존 분할 계획에서 상한을 복구하고 같은 정책의 보류는 자동 해제하지 않는 것도 확인했다. 전체 테스트 255개·타입 검사·프로덕션 빌드 통과; 실제 보류 글의 운영 단건 검증은 별도 완료 기록 전까지 대기다. 가상 응답으로 실제 모델의 사실 보존 품질이나 운영 성공률을 확정하지 않는다.
